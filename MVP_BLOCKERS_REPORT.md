# MVP Blockers Report

Generated by a repository-wide scan for `TODO`, `FIXME`, `HACK`, `MOCK`, `PLACEHOLDER`, `TEMP` across `src/` (case-insensitive), followed by manual verification of every hit that looked load-bearing rather than cosmetic.

**Result of the literal scan:** zero `TODO`/`FIXME`/`HACK`/`TEMP` comments anywhere in `src/`. 46 `MOCK` hits and 208 `PLACEHOLDER` hits, the vast majority of which are legitimate (HTML `placeholder=` attributes on form inputs, image fallback URLs, marketing-page demo content). The findings below are the subset that are real product gaps, found by reading the code behind each hit, not by counting keyword matches.

---

## Launch Blocking

These let a creator interact with a feature that looks real but doesn't persist, doesn't affect any other part of the system, or actively lies about data — directly undermining the stated KPI ("can a real creator make money on Lummy without manual intervention").

| # | Area | File | Issue |
|---|---|---|---|
| 1 | **Inventory** | `src/app/(dashboard)/dashboard/inventory/page.tsx:456-457` | State initialized from `mockProducts`/`mockHistory`, never fetched from a real API. Every stock adjustment a creator makes is local-only and vanishes on refresh — it never touches their real `products` rows. |
| 2 | **Order detail page** | `src/app/(dashboard)/dashboard/orders/[orderId]/page.tsx:247-248` | `mockOrders.find(...) ?? mockOrders[0]` — there is no real fetch at all. A creator opening any order's detail page sees fabricated customer/product/status data, not their actual order. (The orders **list** page is real — only the detail drill-down is fake.) |
| 3 | **Product bundles** | `src/app/(dashboard)/dashboard/products/bundles/page.tsx` | Entire feature is frontend-only: built from `mockProducts`, saved to `localStorage`. No `bundles` table exists in `supabase/migrations/`, no `/api/bundles` route exists. A creator who builds a "bundle" has built nothing that can ever be sold. |
| 4 | **Discount codes** | `src/app/(dashboard)/dashboard/discounts/page.tsx` | Discount codes (e.g. `WELCOME10`) are created and stored in `localStorage` only. Confirmed via grep that neither `src/app/api/checkout/route.ts` nor `src/repositories/order-repository.ts` contains any discount/coupon logic — checkout never validates or applies a code. A creator telling customers "use code X" is telling them to use something that does nothing at checkout. |
| 5 | **Broadcast segments** | `src/app/(dashboard)/dashboard/broadcast/page.tsx:60-69` | Customer segment counts ("All customers: 1,247", "VIP: 89", etc.) are hardcoded fictional numbers, not computed from the creator's real CRM/customer data. A creator sending a "broadcast to 1,247 customers" with 5 real customers is being actively misled about reach. |
| 6 | **Campaigns** | `src/app/(dashboard)/dashboard/campaigns/page.tsx:582` | `useState<Campaign[]>(mockCampaigns)` with no fetch — campaign creation/management is local-only, nothing persists or actually sends anything. |
| 7 | **Referrals** | `src/app/(dashboard)/dashboard/referrals/page.tsx:270-273` | Active referral count, "network revenue," and commission figures are computed from `mockReferrals`, not real data — a creator sees fabricated earnings from a referral program that isn't tracking anything real. |
| 8 | **"Continue with Google" button** | `src/app/(auth)/login/page.tsx:226-238` | Rendered as a fully-styled, clickable button with no `onClick` handler at all. Clicking it does nothing — no error, no redirect, no feedback. Dead UI on the most important conversion page in the product. |

## Why these weren't caught earlier

Items 1-7 above are all dashboard management surfaces that sit *adjacent* to the core "Store → Product → Share → Order → Revenue" loop already certified as code-correct (checkout, payment webhooks, order creation, reconciliation). They look identical in the UI to the real, working pages — same components, same styling — which is exactly why a literal `grep` for `TODO`/`PLACEHOLDER` alone wouldn't have found them; the giveaway was always in the *data source*, not a comment.
